## New on Mac and Windows

- **Background batch imports:** file checks and copying run in the background with progress and cancellation. Playback, search, volume adjustment and group switching remain available. Tracks go to the group selected when the import starts. Duplicate choices include skipping, importing anyway, viewing the existing track, or cancelling the whole batch. Cancellation before the final save discards the batch; the final save completes as one operation. Changes to the library, backup and restore wait until import finishes.
- **Pause / Resume shortcut:** press **M** by default to pause or resume the current track. Change or clear the binding in **Settings → Shortcuts**. It does not start a track from idle. If an existing track already uses M, its binding is preserved; choose another pause shortcut. The pause binding cannot conflict with a track binding in any group.
- **Local MP4 to MP3:** open **Library → Local MP4 to MP3**, select a local MP4 and a save location, then extract the first audio track to a **192 kbps MP3** offline. The original MP4 stays intact. Conversion has progress and cancellation, confirms replacement of an existing destination, and cleans up temporary output after failure or cancellation. Import the saved MP3 separately if you want it in the library.
- **Playback responsiveness:** progress updates avoid refreshing the whole library, and volume dragging avoids repeatedly saving the library. Large-library and import checks measure responsiveness; they do not establish a general CPU reduction or faster total import time.

## Windows interface alignment

The header, Library menu, group chooser, shortcut status, search, track rows, player, shared styles and dialog action order follow the Mac reference. Group rename uses inline Save/Cancel. Track removal asks for confirmation before Recently Deleted. Input padding and menu alignment/focus handling have been refined.

Backup, restore and recovery use the same information hierarchy. **Search YouTube** and **Import from a Link** remain separate windows. Search query and available results are retained across reopening; closing cancels search while an active download continues.

Window controls, file pickers, fonts, key names and global-shortcut permissions retain their platform behavior. Shared layout values do not imply pixel-identical text rendering across operating systems or display scales.

## Installation and existing libraries

Mac installation now starts with **Install SoundKey.command**. Its filename, welcome page, terminal prompts and installer errors are in English. Windows setup and uninstall remain in English; the application itself supports immediate English/Chinese switching on both platforms.

Updating preserves the separately stored music library, groups, bindings and settings. Export a backup from **Library → Back Up and Restore Library** before updating. Windows creates desktop and Start menu shortcuts; Mac opens from Applications.

## Signing

The Mac app uses an **Apple Development** signature. Its Installer package is unsigned, and the release is **not notarized by Apple**. Run the included **Install SoundKey.command**, read its notice, type **INSTALL**, and complete the system Installer. Manual macOS approval may still be required.

The Windows app and installer remain **unsigned**. See the [installation guide](../installation.md) for the current signing status and system prompts.

## Verification scope

Automated smoke coverage includes playback and pause-shortcut behavior, groups and backups, import duplicate/cancel/failure handling, staging cleanup, local MP4 conversion, and performance regressions. Windows automation runs with test substitutes for WPF and audio on the build host; it does not verify native WPF rendering, Windows audio decoding or the operating system's global keyboard hook.

During development, the Mac batch-import interface was exercised with an isolated library, including duplicate choices, cancellation and playback during copying. The local-conversion interface was checked in English and Chinese, and a real local MP4 was converted to a 192 kbps MP3. Those checks do not establish audible quality or behavior on another computer.

Final Mac and Windows Release builds, automated regressions and installer audits passed. Mac passed 27 smoke suites plus two local HTTP imports using the bundled tools; the complete Windows automated suite passed, and its Release build reported no warnings or errors. The Mac package contains build 29. Package audits verified the payload against the final build, archive integrity, English installer content and installation scripts; they did not perform a native install, upgrade or uninstall.

**Native Windows validation of this candidate and the other Mac's first Input Monitoring grant/relaunch flow remain unverified.** The [1.0.1 representative native checks](1.0.1.md#verification-scope) concern that earlier version. Audible quality, real online downloads, full uninstall, legacy-shortcut migration and a broader OS/DPI matrix are also outside this candidate's verified scope.
